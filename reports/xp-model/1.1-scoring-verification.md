# 1.1 - scoring rules verification

`fpl/scoring.py` reproduces the recorded `total_points` for seven hand-checked player-fixtures. Each expected total below was computed from `references/scoring_rules.md` and written into `tests/test_scoring.py` as arithmetic; none of them came from running the function under test.

The five 2025-26 rows span all four positions, both DefCon thresholds, a sub-60 cameo, and a goalkeeper carrying both floor functions.

## The 2018-19 CBIT trap

Tarkowski recorded 19 clearances, blocks, interceptions and tackles in above match, and `merged_gw.csv` carries those raw counts for 2018-19, but defensive contribution did not exist as a scoring event until 2025-26. Scoring that same input under 2025-26 rules returns 9.0, two points above what the season actually awarded. The rules table gates DefCon on season rather than on column presence, so the 2018-19 lookup returns 7.0.

## Floor functions

`E[floor(X)]` and `floor(E[X])` are checked separately from the reproduction tests. A keeper with a degenerate distribution at 7 saves and 5 conceded scores 2.0 and −2.0, not 2.33 and −2.5. A keeper whose save distribution puts half its mass on 2 and half on 4 scores 0.5 save points, where dividing the mean of 3 by three would give 1.0.

## Minutes conditioning

A defender with `P(60+) = 0` scores zero clean-sheet points against a 0.9 team clean-sheet probability, because the clean-sheet term exists only in the 60+ bucket rather than being scaled by expected minutes.

## Open item for the gate

The BPS action table is incomplete. `game_config.scoring.bps` is absent from the public API response, and the site renders that table from a config object the public endpoint does not return, so the per-action BPS values cannot be read from an official source the way the point values can. `BPS_TABLES` therefore holds only the values the rules page and the 2026-27 patch notes state in prose: the removal of the −1 for being tackled, the penalty save drop from 8 to 7, the CBI rate change from 1 BPS per 2 to per 3, and the restructured save values. That is enough for the season-version distinction M1 needs, and not enough to compute a BPS score from match actions. Whether M5 needs the full table depends on whether the bonus component models `bps` directly from the recorded column or builds it up from actions.
